외부 웹에서 앱 안으로 콘텐츠 참여 경험 확장하기

SDK와 외부 참여 경로를 함께 유지하며 기존 콘텐츠의 새 인앱 흐름을 출시했다. 추적 URL·최종 랜딩·외부 폴백을 나누고, 출시 뒤 완료 기록을 할당·회차·이번 클릭에 맞춰 적용한 과정.

주제
#제품 확장 #앱·웹 연동 #SDK

같은 광고 카드를 눌러도 어떤 진입점은 SDK를 사용하고, 어떤 경로는 외부 참여 페이지를 엽니다. 기존 콘텐츠에 인앱 광고 참여를 추가하려면 이후 참여 요청도 실제 실행 환경을 알아야 했습니다. 앱 호출에 실패해 외부로 열리는 경우에는 URL이 전달하는 인앱 참여 여부까지 바꿔야 했습니다.

저는 인앱 참여의 진입·랜딩·복귀·완료 UI를 맡았고 동료는 미디에이션, 즉 광고 공급사를 연결하는 계층을 리팩터링했습니다. 교차 추천은 별도 작업으로 두고 핵심 참여부터 전달하기로 했습니다. 서버·디자인·매체 앱의 역할과 연결하면서 기존 외부 경로도 유지했습니다.

추적 링크와 사용자가 도착할 URL은 같지 않았다

상단 카드와 오퍼월, 콘텐츠 내부 추천은 진입점별 URL 조립 규칙이 달랐습니다. 어떤 진입점에는 최종 콘텐츠 URL을 결정하는 코드(resolver)가 있지만 다른 경로에는 없었습니다.

초기 FE 조립 방식을 바꾸면서, 서버가 최종 콘텐츠 URL에 인앱 표식을 넣은 뒤 추적 링크로 감싸서 내려주는 계약에 맞췄습니다. 화면에서 이미 감싸진 추적 URL을 고쳐도 모든 목적지의 콘텐츠에 같은 인앱 참여 여부가 전달된다고 볼 수는 없었습니다.

실제 콘텐츠 URL에 인앱 참여 여부 연결
  → 추적 URL로 감싸기
  → 사용자 진입
  → 콘텐츠가 인앱 참여 여부를 읽고 참여

클라이언트는 표식을 읽어 실행 방법을 정했습니다. 표식이 있다는 것만으로 실제 앱 실행이나 시청을 인증하지는 않았습니다.

폴백에서는 실패한 실행의 문맥도 바꿨다

앱 인터페이스 호출에 실패해 외부 브라우저를 열면 내부 콘텐츠의 인앱 표식을 제거했습니다. 실제 실행은 외부인데 URL은 인앱이라고 말하면 다음 요청도 잘못된 조건을 읽을 수 있었습니다.

같은 이름의 query라고 아무 목적지에서 지우지는 않았습니다. 내부 콘텐츠의 표식만 다루고 광고주의 동명 파라미터는 보존했습니다. 열기 방식의 폴백이 광고주 URL의 의미까지 바꾸면 안 됐습니다.

복귀 리스너는 화면을 열기 전에 등록했습니다. 빠르게 돌아오는 경우를 놓치지 않기 위해서였습니다. 열기에 실패하면 리스너를 해제했습니다. 화면 열기와 복귀 감시를 함께 시작하고, 열기 실패나 화면 종료 때 감시도 정리하도록 연결했습니다.

먼저 출시한 뒤 완료 표시의 범위를 좁혔다

8월 19일 공동 상용 출시 뒤 동료들의 실제 정상 참여 확인을 받았습니다. 이후에는 완료 UI를 맞추기 위한 로컬 신호를 추가하고 적용 조건을 보완했습니다.

이전 회차에서 완료한 기록이 새 카드의 표시를 바꿀 수 있었습니다. 같은 콘텐츠라고 해도 광고 할당이 다르거나 현재 클릭보다 앞선 완료라면 이번 참여의 근거로 쓸 수 없었습니다.

완료 기록은 다음 조건을 함께 확인하도록 좁혔습니다.

확인할 것필요한 이유
광고 할당같은 콘텐츠의 새 광고를 이전 기록으로 완료 처리하지 않음
회차이전 시간대의 완료를 현재 회차로 이어 쓰지 않음
현재 클릭 이후 시각이번에 시작하기 전의 기록을 새 결과로 읽지 않음

8월 하순에는 할당 조건까지 강화해 후속 통합했습니다. storage와 화면 복귀, 다른 할당·회차·이전 클릭을 무시하는 조건도 회귀 테스트에 포함했습니다.

로컬 기록은 완료 UI를 동기화하는 데 사용했습니다. 외부 폴백에서는 서버의 전환 확인을 유지했고, 승인과 지급도 서버 상태를 따랐습니다. 빠르게 완료를 보여주는 로컬 신호를 서버 판정으로 사용하지 않도록 적용 범위를 나눴습니다.

새로운 실행 경로를 넣으면서 기존 참여를 지키기

사용자는 기존 콘텐츠에서 새 인앱 참여 흐름을 이용할 수 있게 됐고, 실행이 외부로 넘어가는 경로도 남았습니다. 초기에 공동 출시한 결과와 이후 완료 동기화를 보완한 결과는 단계가 달랐습니다.

이 경험에서 문맥을 전달하는 범위를 더 넓게 보게 됐습니다. 인앱 표식을 붙인 URL이 실제로 외부에서 열리면 표식을 바꿔야 했고, 복귀 뒤 완료를 보여줄 때도 이번 할당·회차·클릭의 기록인지 확인해야 했습니다. 기존 제품에 실행 경로를 추가할 때는 새 경로의 정상 동작과 함께, 실패해서 이전 방식으로 돌아간 뒤 어떤 값을 읽게 되는지도 확인해야 한다고 생각합니다.

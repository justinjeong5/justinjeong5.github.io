운영자의 구성과 사용자의 선택을 연결하는 미션 상품 만들기

기존 미션 목록의 규칙을 세트별 설정으로 옮기고, 사용자 선택과 기존 참여 화면을 연결했다. 복제된 식별자와 FE·서버·Gateway의 전달 순서를 다루며 새 상품을 기존 제품에 넣은 과정.

주제
#상품 개발 #운영 도구 #기존 제품 통합

운영자가 여러 미션을 세트로 구성하고 사용자는 그중 하나를 골라 참여하는 상품을 만들었습니다. 사용자에게는 선택 화면이 하나 추가되지만, 운영자는 기존 미션을 복사하고 그룹과 옵션을 바꾸며 새로운 구성을 저장합니다. 두 화면이 같은 상품의 규칙을 읽어야 했습니다.

기존 목록 기준으로만 검증하면 새 상품의 세트별 제한을 확인할 수 없었습니다. 모든 미션을 새 규칙으로 바꾸면 기존 상품의 설정이 달라집니다. 새 상품에는 세트별 검증을 적용하면서 기존 상품의 목록 기준은 유지해야 했습니다.

저는 Gateway의 조회·쓰기 연결과 운영 화면의 검증·복제 입력을 수정했고, 동료들과 사용자 참여 FE를 통합했습니다. 서버는 상품의 저장·선택·참여 정책을 제공했습니다.

선택한 화면과 제출한 선택은 달랐다

참여 화면은 세트 목록과 이미 제출했는지를 조회했습니다. 기존 선택이 있다면 다시 고르게 하지 않고 기존 참여 화면으로 연결했습니다. 아직 제출하지 않았다면 세트를 살펴보고 하나를 선택해 제출할 수 있게 했습니다.

화면에서 미리 고른 상태만으로는 서버에 선택이 제출된 것이 아닙니다. 제출에 성공하면 기존 query를 유지해 참여 화면으로 이어 가고, 실패하면 안내하면서 제출 중 상태를 풀었습니다. 선택 화면에서 들어갈 미션을 확정한 뒤 기존 참여 경로를 사용하도록 했습니다.

검증할 단위를 상품에 맞췄다

운영 QA에서는 기존 목록을 검사하는 범위와 세트마다 검사할 범위를 구별했습니다. 새 상품은 기여 확인(eligibility) 유형의 미션이 세트마다 최대 하나인지 검사하고, 기존 상품은 원래 목록 기준을 유지했습니다.

전체 목록에 검증기를 한 번 적용하면 서로 다른 세트의 미션이 같은 제한을 적용받을 수 있었습니다. UI를 세트별로 나누는 것과 함께, 실제 저장·참여 단위에 맞춰 검증 범위도 나눴습니다.

기존 단가 값과 새 설정의 저장 관계도 QA에서 확인했습니다. 한 화면이 정상적으로 저장되는지만 보는 대신, 다른 상품의 입력이 남아 있는 조건을 함께 읽었습니다.

복제는 같은 내용을 새 대상으로 만드는 일이다

처음에는 복제 문제를 재현하지 못했습니다. 동료가 캠페인을 복사하고 그룹과 옵션을 바꾼 뒤, 기존 미션을 복사하고 다시 세트를 복제하는 순서를 전달했습니다. 같은 순서를 따라가자 단순히 새 세트 하나를 만드는 테스트에서는 보이지 않던 문제가 드러났습니다.

기존 미션 ID를 그대로 넘기면 새 구성을 만들려던 동작이 기존 대상을 가리킬 수 있었습니다. 전체 세트 객체를 복사하기보다 새 template 선택과 복사할 missions 입력을 분리하고, 기존 미션 식별자를 제거했습니다. 세트의 제목·설명도 실제 대상을 표시하도록 보완했습니다.

복사할 미션의 내용
  + 새 세트를 만들 template
  - 기존 미션의 식별자
  → 새로운 구성의 입력

기존 미션의 내용은 재사용하되 기존 대상을 가리키는 식별자는 빼야 했습니다. 객체 전체를 복사하면 새로 만드는 입력에도 기존 관계가 남을 수 있어, 서버로 보낼 값을 나눠 구성했습니다.

코드 통합 뒤에도 전달할 경로가 남았다

서버 반영 뒤 FE를 전달했지만 Gateway 연결이 빠진 조건이 다시 발견됐습니다. 화면·서버·Gateway가 함께 연결돼야 운영 설정과 실제 참여가 이어질 수 있었습니다.

수정과 배포 보고 뒤 동료의 특정 동작 확인을 받았습니다. 이미 잘못 저장된 데이터가 자동으로 고쳐진 것은 아니어서 그 데이터를 재사용하지 않도록 안내했습니다. 코드를 고친 결과와 이전 데이터가 유지하는 결과는 별개였습니다.

재현 순서를 맞춘 QA와 동료의 동작 확인으로 수정 결과를 확인했습니다. 신규 설정을 저장하거나 기존 미션을 반복해서 복사하는 등 운영자가 실제로 만드는 입력 순서를 따라갔습니다.

두 사용자가 같은 상품을 다루게 하기

새 상품은 운영자의 세트 구성에서 사용자 선택과 기존 참여까지 연결됐습니다. 검증 단위를 나누고 복제 입력을 정리하며, 기존 상품의 규칙을 그대로 유지할 범위도 남겼습니다.

이 작업에서는 동료가 재현 순서를 공유해 준 과정이 기억에 남습니다. 처음 확인한 단순 입력에서는 재현되지 않았지만, 운영자는 기존 캠페인과 미션을 계속 재사용하고 있었습니다. 전달받은 복사 순서를 따라가면서 어떤 식별자를 새 입력에서 제거해야 하는지 확인할 수 있었습니다. 운영 도구를 만들 때는 새 기능에 처음 값을 넣는 경우와 함께, 이전 작업의 값을 가져와 다음 구성을 만드는 경우도 확인해야 한다고 생각합니다.

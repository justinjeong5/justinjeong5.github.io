화면 변경의 검사와 전달 경계를 나누기

화면을 조금 바꾸려는데 서버의 검사와 배포도 함께 거쳐야 했다. 화면 개발의 작업 단위와 사용자에게 전달할 경로를 나눈 과정.

담당
제약 설명·팀/인프라 협업·정적 앱/workflow 구현
시기
2023-2024
주제
#전달 구조 #단계 전환 #협업

광고 페이지의 화면 코드는 서버가 HTML을 만드는 템플릿 안에 있었다. 화면을 바꾸는 파일도 서버 프로젝트의 일부였으므로, 화면 개발 작업은 서버의 리뷰·테스트·배포 흐름을 함께 거쳤다.

예를 들어 화면의 문구나 표시 방식을 고치는 변경이라도, 프론트엔드 개발자가 확인한 파일을 바로 별도의 화면 산출물로 전달하는 구조는 아니었다. 화면용 라이브러리와 검사 방법을 재사용하기에도 제약이 있었다. 만드는 사람이 화면 코드만 이해하는 것으로는 변경을 끝까지 전달하기 어려웠다.

그래서 화면을 별도 FE 앱으로 옮기면 된다고 생각하기 쉽지만, 파일의 위치만 바꿔서는 부족했다. 그 앱의 변경을 누가 검토하고, 어떤 검사를 거쳐, 어떤 파일을 배포할지 연결돼야 했다. 따로 만든 화면이 사용자에게 전달되지 않으면 개발 구조만 나뉜 것이다.

이 작업에서 다룬 것은 새 프레임워크를 도입하는 것보다 화면 변경의 작업 단위를 만드는 일이었다. 기존 전달 인프라를 어떻게 이용할지, 이전 경로와 새 경로를 어느 범위에서 함께 둘지도 그 문제에 포함됐다.

독립 앱이 반드시 새 서버를 뜻하지는 않았다

팀과 초기 방향과 범위를 논의하고, 인프라 담당자의 협업을 요청했다. 별도 앱의 개발 구조와 운영 인프라를 혼자 같은 범위로 결정할 수는 없었다.

구현에서는 Next.js를 서버로 실행하는 대신 정적 export를 사용했다. 별도 FE 앱이 만든 파일을 기존 S3·CloudFront 전달 경로에 연결했다. 변경한 것은 앱의 개발·검사·산출물 구성이고, 재사용한 것은 정적 파일을 전달하는 인프라였다. FE 앱을 분리한다고 요청마다 렌더링하는 새 서버까지 같이 운영할 필요는 없었다.

코드 이동보다 중요했던 검사와 산출물의 연결

전달 workflow는 실제 앱을 설치·검사·빌드한 결과를 S3로 동기화하고 CloudFront를 갱신하는 흐름으로 구성했다. 이전의 시험용 동기화 경로에 앱의 산출물을 넣는 것만이 아니라, 그 산출물이 만들어지는 단계부터 연결한 것이다.

앱과 공유 패키지 변경에 대해 lint·format·test를 수행하는 PR workflow도 두었다. 로컬 실행·빌드·검사와 배포 방법을 문서로 남겼다. 화면 개발자가 변경을 만들고 확인하고 전달하는 경로를 같은 앱의 흐름으로 다루려 했다.

리뷰에서 범위를 나누고, 기존 경로와 함께 전환하기

초기 변경에는 새 앱의 전달 구조와 상품 동작, 환경 설정이 함께 들어 있었다. 리뷰에서는 상품 코드와 환경 설정을 다른 PR로 나눠달라는 요청을 받았다. 지금 다시 읽으면 상품의 행동과 전달 환경을 한 번에 설명할 때, 한쪽의 검토가 다른 쪽을 가릴 수 있다는 지적이었다.

전환도 모든 화면을 한꺼번에 옮기는 식으로 끝나지 않았다. 먼저 일부 시험 상품에서 새 경로를 쓰고, 기존 경로와 새 경로를 함께 두었다. 오류 페이지와 남은 상품의 진행 상태도 따로 안내했다.

구·신 경로의 공존은 전환 비용을 없애지 않는다. 어느 상품이 어느 경로를 쓰는지와 오류 페이지·후속 상품의 진행을 계속 구분해야 했다. 그 대신 새 앱의 산출물을 쓰는 범위를 일부 상품에서부터 늘릴 수 있었다.

해당 FE 앱을 개발·검사·전달할 경로가 생겼다

해당 앱을 다루는 개발자는 화면 변경을 설치·검사·빌드하고, 그 정적 산출물을 기존 전달 인프라로 보내는 경로를 사용할 수 있게 됐다. 개발·검사·배포 방법도 같은 앱의 문서에서 확인할 수 있도록 남겼다. 일부 상품을 실제로 새 경로로 전환한 보고까지 이어져, 분리된 폴더가 아니라 화면을 만들고 전달할 작업 단위가 생겼다.

그 경로를 만들 때 인프라 담당자의 협업이 필요했고, 리뷰에서는 상품 코드와 환경 설정을 나눠달라는 요청을 받았다. 화면이 동작하는지뿐 아니라 동료가 무엇을 검토하고 승인할지까지 다른 문제였다는 점이 드러났다. 구·신 경로의 공존 역시 후속 상품의 전환 상태를 계속 읽어야 하는 비용이었다.

지금 이 작업에서 남는 배움은 독립 앱의 의미를 파일 위치나 새 기술 이름으로 설명할 수 없다는 점이다. 변경을 확인할 책임, 배포의 입력, 남겨둘 기존 경로가 함께 정해져야 다른 사람이 다음 화면을 옮길 때도 사용할 수 있다. 전달 구조를 만든 일은 동료가 이어서 작업할 수 있는 경로를 남기는 일이기도 했다.

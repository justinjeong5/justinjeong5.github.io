AI와 협업하는 작업 인계: 코드·계획·데이터의 맥락

실제 서버 변경을 요청하고 FE 계획과 쿼리 설명을 전달하며, 다음 작업이 무엇을 입력으로 받아야 하는지 정한 경험.

앱 안에서 광고를 보여주는 기능을 연동하기 전에 서버 담당자에게 배포에 사용한 PR과 브랜치를 요청했다. 서버가 준비됐다는 소식은 받았지만, Codex에게 호환성을 미리 검토하게 하려면 실제 변경이 필요했다. 담당자는 요청한 자료를 전달했다. 이 장면에서 먼저 해결한 것은 구현보다 분석에 사용할 입력이었다.

AI와 작업을 연결할 때 앞 단계의 요약만 넘기면 다음 단계는 빠진 맥락을 가정으로 채울 수 있다. API가 제안인지 구현인지, 어떤 변경이 반영됐는지, 결과를 누가 소비할지가 있어야 다음 질문도 구체적이 된다. 서버 연동 준비와 FE 플래닝, 제품 분석 자료를 만들면서 그 차이를 보았다.

완료 소식과 실제 변경은 다른 입력이었다

서버 작업은 검증 환경에 배포되어 있었다. 나는 실제 FE 연동 전에 Codex에게 호환성을 확인해 보려 한다고 설명하고 그 배포에 사용한 변경을 요청했다. 무엇이 바뀌었는지 추측하게 하기보다 담당자가 제공한 PR과 브랜치를 분석의 출발점으로 삼으려 했다.

이때 확인된 결과는 분석할 자료를 확보한 데까지다. 이 요청만으로 호환성 검토가 끝났거나 문제를 찾아 수정했다고 설명할 수는 없다. 그래도 다음 작업의 조건은 달라졌다. 서버가 준비됐다는 말에 의존하는 계획과 실제 변경을 읽고 세우는 계획은 출발점이 다르다. 지금 돌아보면 작업 인계에서 중요한 것은 완료라는 표현보다 다음 사람이 읽을 대상이었다.

FE 계획을 나눠야 다른 담당자가 사용할 수 있었다

제품 개발 플래닝에서는 제품 담당자가 PRD를 업데이트하고 서버 동료가 서버 계획을 준비했다. 나는 Claude의 도움으로 FE의 API, 상태, 광고, 문의, 계측과 리뷰·검증 작업을 나누어 전달했다. 한 기능의 설명을 길게 확장하는 대신 프론트엔드에서 이어야 할 일을 구분했다.

API 연결만 있는 계획으로는 참여 후 상태를 언제 갱신할지, 광고 실행 뒤 무엇을 안내할지, 문의 경로와 이벤트를 어디에 연결할지가 잘 보이지 않는다. 당시 전달한 계획에는 그 영역들이 함께 있었다. 제품 담당자는 일정 산정에 감사했다. AI의 계획을 팀의 확정 사양으로 대신하기보다 각 담당자가 준비한 입력 위에 FE의 작업 범위를 설명한 결과였다.

쿼리도 다음 사용자를 위한 설명이 필요했다

제품 담당자들이 리텐션, 보상 수령, 콘텐츠 진입과 복귀를 보고 싶다고 했을 때도 먼저 현재 수집 데이터로 답할 수 있는지 확인하겠다고 했다. 그 뒤 Claude와 이벤트 분석과 쿼리 설명 자료를 만들었다. 쿼리만 전달하면 동료는 항목의 의미부터 다시 읽어야 하므로 질문을 좁히고 분석과 설명을 함께 붙였다.

동료는 자료의 활용 의사를 보였고 검증 절차가 포함된 점에도 반응했다. 자동으로 갱신되는지 묻는 질문에는 아직 자동화하지 못했다고 답했다. 전달한 것은 동료가 이해하고 확장할 수 있는 자료였다. 여기서 다음 사용자에게 필요한 맥락은 코드 버전과 달랐다. 무엇을 보려는 쿼리인지와 결과를 어떤 질문에 사용할지가 자료의 일부였다.

설정 파일만 넘기면 빠지는 맥락

배포 선택기에서는 설정 파일만으로 다음 확인의 입력이 충분하지 않았다. 소비 저장소의 선언과 이를 읽는 도구 버전, 구 전용 분기가 제거됐는지를 함께 정해야 새 경로의 결과를 읽을 수 있었다. 이 조합을 직접 배포해 동작을 확인한 과정은 배포 환경의 표시 계약에 정리했다. 인계할 맥락은 파일 하나가 아니라 그 파일이 어떤 소비 상태에서 읽히는지였다.

다음 작업이 가정하지 않아도 되는 결과

서버 연동 준비에서는 실제 변경을 확보했고, 플래닝에서는 FE가 맡을 영역을 나눠 전달했다. 분석 자료에는 질문과 쿼리 설명을 붙였고 배포 도구에서는 소비하는 버전을 함께 정했다. 같은 AI 작업이어도 다음 담당자가 필요한 입력은 서로 달랐다.

현재 이 경험들을 돌아보면 작업을 연결한다는 것은 명령을 순서대로 실행시키는 것보다 넓다. 앞 단계의 계획을 다음 단계의 확정 사실로 바꾸지 않고, 자료 확보와 검토 완료를 구별하며, 받는 사람이 무엇을 판단할지 설명하는 일이다. 그 맥락이 있어야 AI가 만든 결과도 팀의 다음 작업에 들어갈 수 있었다.

AI 구현 이후의 책임: 검토·실행·운영 반영

AI와 준비한 코드, DBA가 반영한 DB, 직접 확인한 배포는 같은 완료가 아니었다. 다음 반영이 기다릴 신호와 맡을 사람을 정한 경험.

문의 기능의 서버 코드를 AI와 준비해도 DB까지 준비된 것은 아니었다. 검토용 변경을 DBA에게 전달하고 담당자의 반영 완료 보고 뒤 서버 변경을 병합했다. 다른 배포 도구 작업에서는 AI에 구현과 PR 준비를 맡기되 배포와 동작 확인은 직접 진행했다.

두 작업 모두 구현에 AI를 활용했지만 마지막에 할 일은 달랐다. 직접 확인할 동작과 담당자의 완료를 받아야 할 상태를 구분해야 다음 단계로 넘어갈 수 있었다.

수정안을 검토하는 것과 실행하는 것은 달랐다

문의 서버 변경에서는 미지원 요청의 거절뿐 아니라 DB 저장·외부 생성·자동 처리가 시작되지 않는 조건을 테스트에 남겼다. AI가 준비한 수정안을 수용할 때의 기준이었다. 익숙하지 않은 서버 영역을 맡은 과정에서 이 판단을 자세히 다뤘다.

DB에는 기존 ENUM 순서를 유지하고 새 값을 마지막에 추가하는 검토용 DDL을 준비했다. 화면의 표시 순서는 별도로 다뤘다. 자료를 준비하는 일과 공유 DB에 실제로 반영하는 일은 담당자가 달랐다. 코드 검토를 마쳤다는 신호로 DB 반영의 완료를 대신할 수는 없었다.

운영 반영의 완료는 담당자가 확인했다

DBA는 현행 스키마와 실행 방식을 검토하고 운영·검증 환경에 새 값을 반영했다. 나는 DB 반영 완료 뒤 서버 변경을 병합하기로 정하고 담당자의 완료 보고를 받아 그 순서로 진행했다. 코드가 준비됐다는 결과를 실제 DB의 준비 상태로 대신할 수 없었다.

여기에는 서로 다른 책임이 있었다. AI와 나는 기존 서버 경로를 조사하고 구현과 테스트를 준비했다. DBA는 공유 DB에서 실행할 변경을 검토하고 반영했다. 나는 그 결과를 다음 병합의 조건에 연결했다. 같은 기능 안에서도 수정안, 실행, 다음 반영을 하나의 완료로 묶으면 준비되지 않은 의존성을 지나칠 수 있었다.

직접 확인할 끝점은 작업에 따라 달랐다

배포 도구 개선에서는 AI에 구현과 PR 준비를 맡기고 배포는 직접 하겠다고 정했다. 소비 저장소의 선언과 구 전용 분기 제거가 함께 들어간 버전에서 선택과 실제 배포를 확인했다. 그 작업에서 직접 맡은 끝점은 소비 버전의 동작이었고, 문의 기능에서는 DBA의 반영 신호를 받아 서버 병합을 이어가는 순서였다.

배포 설정과 소비 버전은 첫 번째 확인을 자세히 다룬다. 문의 기능과 DB 반영에서는 코드와 공유 DB를 연결한 과정을 정리했다. 두 작업은 구현을 위임한 사실이 닮았지만, 내가 직접 실행할 일과 담당자의 결과를 받아야 할 일이 달랐다.

성공을 받아들일 조건을 남기기

문의 기능에서는 DBA의 반영 완료를 받아 서버 병합을 이어 갔고, 배포 도구에서는 소비 버전의 동작을 직접 확인했다. 같은 '구현 완료' 뒤에도 필요한 행동과 확인할 사람이 달랐다.

지금 다시 위임 범위를 정한다면 끝에 막연한 재검수를 남겨두기보다, 직접 실행할 확인과 담당자가 알려줄 완료를 적고 싶다. 이 작업에서도 그 둘을 구체적으로 나누어야 다음 단계가 준비된 상태에서 시작할 수 있었다.

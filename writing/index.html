광고·리워드 제품

광고·리워드 제품을 만들고 운영하며 화면, 진단, 서버 협업, 배포까지 다룬 기록입니다.

  • 관측 설계2026.08–2026.09

    참여 지표는 지키고 진단 로그만 줄이기

    참여 지표는 수집 대상에서 제외하지 않고 상세 진단만 기기 고정 2% 표본으로 줄였습니다. 데이터 플랫폼 담당자는 8월 적용 뒤 진단 이벤트 약 86%, 당시 BI 전체 이벤트 처리량 약 54% 감소를 보고했습니다. 표본 밖 문의를 위한 별도 조사 경로도 남겼습니다.

  • 콘텐츠 제품2026.09

    같은 기사에 새 광고가 붙었을 때, 무엇을 다시 측정할까

    기사 카드는 그대로여도 광고 할당은 바뀔 수 있습니다. 화면의 콘텐츠와 노출의 기준을 분리해 새 할당의 누락을 고쳤습니다.

  • 서버 협업2026.08

    화면에서 숨긴 문의를 서버에서도 막기까지

    문의 분류를 화면에서 숨기는 것만으로는 직접 생성 요청을 막을 수 없었습니다. 프론트엔드 밖의 Python 서버에서도 저장·외부 처리 전에 검증하고, DB가 준비된 뒤 코드를 병합했습니다.

    PlayHub 초기 구축부터 앱·웹 참여 확장까지

    PlayHub 초기 허브의 핵심 프론트엔드를 구축하고 앱·웹 반복 참여로 확장했습니다. 같은 서버 상태에서 다음 행동을 정하되 완료를 확인하는 방법은 환경별로 나눠 두 금융 파트너 앱 출시까지 연결했습니다.

  • WebView 진입2026.06

    Quest 링크가 빈 화면에 머문 지점을 찾고, 페이지 이동을 없애다

    파트너 앱의 Quest 링크에서 빈 화면이 재현됐습니다. 새 화면의 응답 도착과 실제 화면 전환을 분리해 관찰하고, 지연이 남은 페이지 이동을 없애면서 URL과 레이아웃 조건을 보존했습니다.

  • 공용 광고 실행2026.01–2026.04

    내부 노출 기록과 실제 SDK 실행이 어긋난 제품을 조사했습니다. 후보를 소비하는 FE의 누락 분기를 찾아 실행과 결과 처리까지 연결했습니다.

  • 추천·보너스2025.06–2025.07

    추천 배너에서 약속한 보너스가 다음 화면에서 사라지지 않게

    추천을 눌러도 일반 참여로 이동하면 도착 화면은 보너스를 알 수 없습니다. 추천 경유 참여 ID를 받은 뒤 이동하고 서버의 혜택·만료를 각 화면에서 사용했습니다.

    적립 요청이 성공해도 문의가 끝나지 않았을 때

    운영자가 한 문의의 근거를 확인하고 적립을 처리하는 화면을 만들었습니다. 출시 뒤 요청 성공과 상태 반영 사이의 시간차가 드러나자, 확인 중·반영 확인·추가 확인을 다른 상태로 안내했습니다.

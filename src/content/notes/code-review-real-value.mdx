## 지적이 실제 경로에 닿는가

코드가 어떻게 호출되고 어떤 입력에서 문제가 생기는지 확인한다. 기존 가드·타입·테스트·설정이 이미 막는지 반대 근거도 읽는다. 동의나 지적 개수 자체는 정확성의 증거가 아니다.

## 수정의 범위도 선택이다

관련 없는 문제는 좋은 아이디어여도 같은 변경에 넣을지 따로 판단한다. 제안을 적용하지 않을 때도 이유와 검증 경계를 남긴다. 수정 후에는 바뀐 경로와 영향을 받는 소비자를 다시 확인한다.

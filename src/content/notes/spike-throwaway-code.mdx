## 버릴 코드의 목적도 분명해야 한다

한 가지 질문을 확인한다. 실제 응답의 형태는 무엇인가, 특정 환경에서 어떤 경로가 실행되는가, 최소 조건에서 계약이 유지되는가. 환경·입력·관찰 결과와 아직 모르는 부분을 남긴다.

실험은 좁은 조건을 확인한다. 성공한 샘플을 모든 입력이나 운영 결과로 확대하지 않는다. 본제품에 옮길 때 필요한 예외·검증·배포 경계는 별도다.

## 적용할 때 다시 보는 것

의존성, 데이터 계약, 책임 범위, 실패/정리 경로를 확인한다. 코드를 언제나 전부 버려야 하는 것도, 빠르게 동작하는 코드가 바로 제품 코드인 것도 아니다. 재사용 여부는 확인한 제약과 비용으로 정한다.

## 응답은 상태 코드보다 많은 것을 말한다

HTTP 성공과 서비스 body의 오류, 정상 빈 결과와 수집 실패를 나눈다. 여러 소스가 모이면 전체 성공·부분 성공·실패의 의미도 먼저 정의한다. 성공한 일부 데이터를 모두 버릴지, 불완전함을 표시하고 유지할지도 제품의 계약이다.

공급자의 속도 제한·오류·응답 형태를 한 값으로 합치지 않는다. 정책을 나눠도 공통 자원과 전체 작업 시간 같은 영향은 남을 수 있다.

## 끝까지 읽었다는 조건

페이지 번호·cursor·마지막 페이지의 의미는 공급자별로 확인한다. 요청 상한이 있다면 그 상한을 넘는 응답과 전체 자료를 구분해야 한다. 일부만 읽고도 완료 상태를 올리는 실패는 눈에 덜 보인다.

로그는 원문 요청/응답을 무조건 남기기보다 상태·오류 종류·시점·처리 수처럼 필요한 범위로 제한한다. 비밀값과 사용자 식별자는 별도 보호 대상이다.

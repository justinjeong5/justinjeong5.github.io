## 실행 작업만 없어지는가

자동화가 작성이나 수집을 맡아도 입력 확인, 오류 판정, 공개 내용 검토와 복구는 남을 수 있다. 구현 가능성과 운영 가능성을 같은 질문으로 묶지 않는다.

기존 자동화 PoC 글에서 반복된 운영 부담과 검토 경계의 질문을 남겼다. AI가 추정한 운영 확률이나 기대 시간은 실제 이용률·절감 효과로 사용하지 않는다.

## 비교할 선택지

전체 자동화, 좁은 자동화, 사람이 결정하는 검토 경계를 나눠 본다. 되돌릴 수 있는 내부 출력과 공개 이후 회수하기 어려운 정보도 다르다. 운영자의 제약은 도구가 대신 추측할 사실이 아니라 설계 입력이다.

검토가 계속 늘거나 결과를 읽는 기준이 흐려지면 실행이 빨라져도 목적은 가까워지지 않을 수 있다. 효과를 말하려면 실제 사용·실패·변경 비용을 관찰해야 한다.

## 일을 맡겼다는 것의 확인

검사 명령, source, 실제 환경과 사용자 결과를 구분한다. AI가 동의했다는 이유로 완료 상태나 외부 실행 권한을 올리지 않는다.

기사 섹션을 QA할 때 재할당 뒤의 노출이 빠지는 조건을 확인했습니다. 화면에는 같은 기사가 남아 있지만 계측할 광고는 새로운 회차였습니다. 카드가 그대로라는 사실만으로 이전 노출 타이머를 계속 써도 되는 것은 아니었습니다.

디자이너가 만든 카드 원형에는 이미지와 제목, 넘기기와 누르기 반응이 있었습니다. 제품에 연결하려면 화면에 표시할 콘텐츠와 사용자가 참여할 광고, 기록할 노출을 각각 구분해야 했습니다. 시안에 API를 붙이더라도 이들을 한 객체로 읽으면 같은 기사가 새 광고로 할당됐을 때 참여와 계측이 어긋났습니다.

PlayHub의 기사 섹션은 리워드 안내보다 콘텐츠의 매력을 앞세워 참여 반응을 확인하려는 시도였습니다. 실제 리워드가 없는 상품으로 바꾼 것은 아닙니다. 제품 가설과 시각 표현은 동료들의 작업이었고, 저는 **그 원형에 실제 데이터를 넣고 참여·복귀·계측이 이어지도록 연결하는 FE 통합**을 맡았습니다.

## 화면의 모델을 API의 객체와 분리했다

원형이 사용하던 미션·광고 모델을 카드에 그대로 넘기면 응답 구조와 표현, 참여 로직이 함께 바뀝니다. 기사 카드가 필요한 식별자·제목·이미지·클릭·노출 정보를 독립 표시 모델로 만들고 준비 함수를 두었습니다.

디자인 shell과 누를 때의 표현은 유지했습니다. 입력과 callback을 콘텐츠 기준으로 바꾸고, 중복 제거와 표시 상한, 진단용 metadata는 준비 단계로 옮겼습니다. 이미지를 표현하는 변경이 참여 가능한 데이터를 판단하는 코드를 함께 건드릴 이유를 줄였습니다.

준비 함수의 입력은 런타임에서 검증하지 않은 `unknown`이었습니다. TypeScript 응답 타입은 개발 중의 약속이지, 실제 서버 객체가 그 구조라는 증거는 아니었기 때문입니다.

## 모든 실패를 빈 목록으로 바꾸지 않았다

전체 응답 구조가 잘못된 것과 정상 목록 안의 한 항목이 손상된 것은 다른 상황입니다. 둘을 모두 빈 배열로 만들면 조회 실패가 정상적인 콘텐츠 소진처럼 보입니다.

| 입력의 문제 | 사용할 결과 |
| --- | --- |
| 바깥 응답 구조가 잘못됨 | 조회 오류 |
| 정상 목록이 비어 있음 | 정상적인 콘텐츠 없음 |
| 항목의 참여 필수값이 잘못됨 | 해당 항목 제외, 이유 기록 |
| 참여 데이터는 유효하고 이미지만 실패 | 대체 이미지 표현 |

식별자·제목·클릭·계측 URL처럼 다음 행동에 필요한 값은 필수로 확인했습니다. 클릭할 수 없는 카드를 예쁜 이미지가 있다는 이유로 보여주면, 사용자가 눌렀을 때 작업이 끊깁니다. 반대로 이미지 실패 때문에 유효한 참여 전체를 버릴 필요는 없었습니다.

공개 URL은 HTTPS와 인증정보가 없는 형식을 확인하고, 개발용 로컬 HTTP 허용은 명시 옵션으로 나눴습니다. 입력 형식의 검사와 모든 목적지의 신뢰성을 보증하는 것은 다른 범위였습니다.

## 새로운 섹션은 기존 추천을 덮으면 안 됐다

처음의 클라이언트 분할 경로에서 서버의 섹션 계약을 쓰는 방향으로 바꿨습니다. 기사 콘텐츠는 전용 섹션으로 조회하고, 기존 추천 요청에는 그 파라미터를 넣지 않았습니다. 섹션을 지정하지 않은 기존 응답에 새 콘텐츠가 섞이지 않는지도 서버와 확인해 계약을 맞췄습니다.

복귀 뒤 재조회도 같은 구분을 따라야 했습니다. 호출 때마다 옵션을 기억하게 하기보다 hook을 만들 때 대상 query key를 고정했습니다. 기사에서 돌아오면 기사 query를, 추천에서 돌아오면 추천 query를 갱신했습니다.


## 같은 기사라고 같은 노출은 아니었다

화면에는 같은 기사가 계속 남아 있는데 광고 할당이 바뀔 수 있었습니다. 콘텐츠 ID만으로 노출을 판단하면 새 할당을 놓치고, 배열 객체가 바뀔 때마다 새 노출로 읽으면 불필요하게 다시 기록합니다.

독자에게는 같은 기사여도 계측에서는 새로운 회차였습니다.

표시에 사용할 콘텐츠 식별자와 계측의 할당·항목 식별자를 나누었습니다. 실제 할당 과정의 요청 식별자를 응답에 연결하는 작은 서버 변경에도 참여했습니다. 표시용 새 ID를 만들어 주는 것이 아니라, 계측이 읽어야 할 회차를 전달하는 변경이었습니다.

대상의 계측 식별자가 바뀌면 이전 노출 타이머를 취소하고 새 회차로 측정했습니다. React가 같은 카드를 유지하는 기준과 광고 노출이 새로 시작되는 기준은 같지 않았습니다. QA에서 재할당 시 노출이 빠지는 조건을 확인하고 수정 동작을 확인했습니다.

## 복귀를 기다리는 동안 다른 카드를 열 수 있었다

사용자가 외부 페이지에서 돌아와 재조회하는 동안 다른 콘텐츠를 열면 복귀 감시 listener가 교체될 수 있습니다. 이전 감시의 잠금이 남거나 늦은 완료가 새 시도를 건드리면 다음 행동이 막힙니다.

교체 때는 취소 callback으로 이전 잠금을 정리하고, 종료 여부와 generation으로 늦은 완료의 적용을 제한했습니다. 정상 복귀만 따라가면 보이지 않는 순서였습니다.

```text
A 열기 → A 복귀·재조회 시작
  → B 열기, 감시 교체
  → A의 늦은 완료는 B 상태를 바꾸지 않음
```

표현 단계의 이미지 fallback과 구형 모바일 보완도 이어졌습니다. 디자인의 색상 알고리즘을 처음 만든 작업은 동료의 기여이고, 제가 맡은 부분은 이를 실제 데이터와 실행 흐름에 통합하는 일이었습니다.

## 시안에서 상용 콘텐츠까지

9월 초 시각 원형을 받은 뒤 표현과 참여 QA를 진행했습니다. FE 배포 뒤 동료들의 공급·유닛 설정과 제한된 참여·적립 확인을 거쳐, 9월 9일 상용으로 전환됐습니다. 출시 다음 날에는 후속 회귀 테스트도 보강했습니다. 구현 뒤에 확인된 조건도 다시 테스트에 남기며 통합의 경계를 이어서 다뤘습니다.

내부 참여에서는 새 섹션이 눈에 띈다는 반응과 제목·소재 잘림 의견이 있었습니다. 초기 관측에는 QA가 섞여 있어 장기 클릭률이나 매출 변화로 정리하지 않았습니다. 확인된 제품의 변화는 사용자가 새 기사 카드를 열고 돌아올 수 있고, 기존 추천은 자기 조회를 유지하며, 데이터 손상·재할당·감시 교체가 각각 다른 결과로 다뤄지는 것이었습니다.

시안을 제품에 연결하면서 “보이는 카드”와 “참여할 수 있는 입력”, “새로 기록할 노출”을 서로 다른 대상으로 다뤘습니다. 다음 원형에서도 표현을 옮기기 전에 어떤 입력으로 행동을 허용하고 어떤 식별자로 결과를 기록할지 확인하려 합니다.

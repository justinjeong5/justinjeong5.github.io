참여형 서비스에 기사 콘텐츠를 보여주는 새 섹션이 들어왔다. 제품 담당자는 매력적인 콘텐츠가 있을 때 사용자가 자발적으로 읽는지 확인하려 했다. 보상 안내를 앞세우지 않는 표현을 사용했지만 실제 보상이 없는 상품으로 바꾼 것은 아니었다.

디자이너가 만든 원형에는 가로로 넘기는 카드, 제목과 새 콘텐츠 표시, 이미지 하단의 색상 표현, 누를 때의 반응이 있었다. 화면의 모습과 움직임은 준비됐지만 실제 API에서 어떤 콘텐츠를 받고, 클릭 후 어디로 이동하며, 돌아왔을 때 무엇을 다시 조회할지는 제품 코드에 연결해야 했다. 내가 맡은 일은 그 원형을 실제 데이터와 참여 수명주기 안에 넣는 것이었다.

## 시각 원형과 제품 모델의 책임을 나누었다

원형은 기존 미션·광고 모델을 이용했다. 이를 그대로 새 카드의 입력으로 쓰면 API 응답의 구조와 화면 표현, 참여 로직이 한 컴포넌트 안에 붙는다. 기사 카드에 필요한 식별자·제목·이미지·클릭·노출 정보를 담는 독립 표시 모델과 준비 함수를 만들었다.

디자인 shell은 유지하면서 입력과 callback을 콘텐츠 기준으로 바꾸었다. 중복 제거와 표시 상한, 진단용 metadata도 준비 단계로 옮겼다. 새 모델이 생겼다는 사실이 카드 디자인과 색상 표현을 내가 처음 만들었다는 뜻은 아니다. 이미 만들어진 화면을 제품의 데이터 경계에 맞게 연결한 변경이었다.

이 분리를 통해 이미지 표현을 바꾸는 작업과 콘텐츠가 참여 가능한지 판단하는 작업을 서로 다른 곳에서 다룰 수 있었다. API의 객체를 카드가 그대로 신뢰하지 않도록 한 것도 그 경계에 포함됐다.

## unknown 응답을 어느 단위에서 실패시킬 것인가

TypeScript에 응답 타입이 있어도 서버가 그 모양을 반환했다는 런타임 보장은 없다. 미검증 응답을 `unknown`으로 받고, 확인한 값만 표시 모델로 변환했다. 식별자와 제목, 클릭 URL과 계측 URL처럼 참여에 필요한 값은 필수로 검사했다.

응답의 바깥 구조가 잘못되면 조회 오류로 처리했다. 정상 목록인지조차 알 수 없는 응답을 빈 목록으로 바꾸면 계약 위반을 콘텐츠 소진으로 오해하게 된다. 반면 목록 안의 일부 항목만 손상됐다면 그 항목을 제외하고 이유를 남겨 정상 콘텐츠는 표시했다.

이미지는 또 다른 실패 단위였다. 이미지가 없거나 잘못됐더라도 클릭과 계측에 필요한 데이터가 유효하다면 대체 표시로 남길 수 있었다. 한 장의 이미지 실패 때문에 콘텐츠 참여까지 버리거나, 클릭에 필요한 값이 없는 항목을 보기 좋은 카드로 남기는 두 경우를 구별했다.

공개 환경에서는 HTTPS이며 인증정보가 포함되지 않은 URL을 사용하도록 검사했다. 개발용 로컬 HTTP 허용은 명시 옵션으로 분리했다. 이것은 공개 콘텐츠가 사용할 URL 형식의 경계이며, 모든 목적지의 신뢰성을 보증하는 정책으로 확대하지 않았다.

## 새 섹션이 기존 추천의 조회를 바꾸지 않게 했다

처음에는 클라이언트가 섞인 콘텐츠를 나누는 경로가 있었지만 실제 구현은 서버의 섹션 계약을 사용하도록 바꾸었다. 기사 콘텐츠는 전용 섹션으로 조회하고 기존 추천 요청에는 그 파라미터를 넣지 않았다. 서버 담당자에게도 섹션을 지정하지 않은 기존 응답에 새 콘텐츠가 섞이지 않는지 확인했고, 해당 응답 계약은 서버에서 수정됐다.

외부 콘텐츠에서 돌아온 뒤 재조회하는 대상도 같은 구분을 따라야 했다. 호출할 때마다 옵션을 기억하게 하는 대신 hook을 만들 때 조회 키를 고정했다. 기사 콘텐츠의 복귀는 기사 query를, 기존 추천의 복귀는 추천 query를 정확히 갱신하도록 연결했다.

새 기능의 성공을 다른 query의 완료로 읽거나 기사 응답으로 기존 추천을 덮는 일을 막으려면, 화면 구역의 분리만큼 데이터의 소유권도 명확해야 했다.

## 같은 카드와 같은 광고 노출은 같은 뜻이 아니었다

화면에 같은 기사가 계속 보여도 광고 할당이 바뀔 수 있었다. 콘텐츠 식별자만으로 노출을 구분하면 새 할당을 이전 카드로 간주해 계측하지 않을 수 있다. 반대로 배열 객체가 새로 만들어졌다는 이유만으로 노출을 다시 기록해서도 안 된다.

화면의 콘텐츠 식별자와 계측에 필요한 할당·항목 식별자를 구분했다. 실제 할당의 식별자를 응답에 전달하는 작은 서버 변경에도 참여했다. 응답용 새 UUID를 생성하는 대신 할당 과정에서 만들어진 요청 식별자를 그대로 전달하도록 기존 서버 관례에 맞췄다.

노출 관찰 컴포넌트는 대상의 계측 식별자가 바뀌면 이전 타이머를 취소하고 노출 시간을 다시 측정하도록 보완했다. React의 표시 key와 광고 노출의 회차가 항상 같은 단위는 아니었다. QA 환경에서는 재할당 때 노출이 누락되는 조건을 확인하고 수정된 동작을 확인했다.

## 돌아오는 동안 다른 콘텐츠를 열면 누구의 완료인가

콘텐츠 클릭에는 중복 실행을 막는 잠금과 복귀 감시가 있었다. 외부 페이지에서 돌아와 재조회하는 도중 다른 콘텐츠를 열면 감시 listener가 교체될 수 있다. 기존 감시의 취소가 잠금을 남기거나 늦은 완료가 새 시도를 덮으면 다음 행동이 막힌다.

복귀 감시의 교체에서는 취소 callback으로 이전 잠금을 정리하고, 종료 여부와 generation을 확인해 늦은 이전 완료가 새 시도를 수정하지 않도록 했다. 요청을 한 번 시작했다는 사실보다 지금도 그 시도가 상태를 바꿀 자격이 있는지가 중요했다.

이미지 하단 색상도 실제 viewport 진입과 이미지 load 이후에 처리하는 후속 변경이 통합됐다. 이미지 표현 실패의 fallback, 구형 모바일 환경의 보완과 복귀 잠금은 시안을 제품으로 옮긴 뒤 남는 실제 사용 조건이었다. 최종 결과는 디자인 작업과 런타임 작업이 함께 들어간 공동 통합이었다.

## FE 배포에서 상용 전환까지 이어졌다

프론트엔드를 배포한 뒤 서버·운영 담당자의 공급 및 유닛 설정, 실제 참여 확인을 거쳐 9월 9일 상용으로 전환됐다. 참여 QA에는 동료들의 적립 확인이 있었고, 내부 참여에서는 새 섹션이 눈에 띈다는 반응과 제목·소재 잘림에 대한 의견도 있었다.

출시 직후 관측 자료에는 출시 전 QA와 초기 반응이 섞여 있어 장기 클릭률이나 매출의 변화를 말하기는 어려웠다. 출시 다음 날에는 후속 회귀 테스트도 보강했다. 복귀 재조회 중 다른 콘텐츠를 여는 경우와 계측 대상이 교체되는 조건 등을 코드와 테스트에 남기며 통합 이후의 경계를 이어서 다뤘다.

사용자는 새 기사 카드를 열고 돌아올 수 있게 됐고, 기존 추천은 자신의 조회 경로를 유지했다. 디자이너의 원형을 살리면서도 일부 데이터 손상, 새 할당, 감시 교체가 각자 다른 결과로 처리되게 만든 것이다. 이 작업은 시안을 옮기는 일이 데이터 검증과 참여 상태, 계측의 단위를 결정하는 제품 개발이기도 하다는 점을 남겼다.

## 확인 근거와 공개 범위

요청·상태 경계의 코드·리뷰와 mock ky 기반 테스트 파일을 대조했습니다. 실제 서버 취소·기기 동작·정산을 검증한 결과로 확장하지 않습니다.

이 글은 원문을 대조한 공개용 재구성입니다. 내부 코드·협의 원문·고객 정보는 공개하지 않으므로 방문자가 원문을 직접 검증할 수 있는 자료는 아닙니다.

## 대기 시간을 더하는 대신 경계를 좁혔다

광고 판정에서 이전의 빈 조회 결과가 최신 요청의 결과처럼 쓰이는 경로를 다뤘다. 고정 대기 시간을 늘리는 대신 보너스 판정의 요청 경계만 일반 조회와 분리하는 방향을 택했다.

공용 fetcher와 일반 Query 정책은 유지했다. 전체 캐시를 없애거나 모든 광고 흐름을 같은 정책으로 바꾸는 작업이 아니었다.

## 응답과 정리 작업에 식별 관계를 두었다

요청 키와 세대 값을 사용해 현재 요청에 대응하는 결과만 상태에 반영하는 가드를 구현했다. 재조회·초기화·비활성화/정리 시 이전 취소 신호와 세대 변경을 다뤘다.

이전 요청의 정리 작업이 새 요청의 controller를 지우는 것 역시 별개의 경계다. 결과를 적용할 때뿐 아니라 정리할 때도 현재 활성 요청과의 식별 관계를 확인했다.

## 테스트가 다루는 층

mock HTTP 클라이언트를 통해 취소 신호가 전달되고 새로운 응답이 반영되는 시나리오를 통합 테스트에 구성했다. 이 구조를 실제 서버의 요청 취소나 실기기의 결과 확인으로 바꾸지 않는다.

요청 최신성의 source 계약이 이 기록의 범위다. 다른 무응답 문제와 같은 원인으로 합치거나 완료율·매출 개선을 더하지 않는다.

[원래 소비자 계약을 유지하는 관측](/cases/bridge-observation-contract)도 새로운 기능을 좁은 경계에 추가하는 별개의 기록이다.

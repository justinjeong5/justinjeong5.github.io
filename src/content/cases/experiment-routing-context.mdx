## 확인 근거와 공개 범위

요청·컨텍스트 경계의 코드·리뷰를 대조했습니다. 후속 보고를 이 변경 하나의 효과로 귀속하거나 실험 성과를 추정하지 않습니다.

이 글은 원문을 대조한 공개용 재구성입니다. 내부 코드·협의 원문·고객 정보는 공개하지 않으므로 방문자가 원문을 직접 검증할 수 있는 자료는 아닙니다.

## 분기 위치가 여러 곳이었다

추천 배너를 특정 조건에 맞춰 노출하는 흐름에서 판별이 여러 경로에 걸쳐 있었다. 서버의 판별을 외부 API로도 사용할 필요를 설명하고 요청했다.

이 요청이 실제 서버 구현의 채택까지 증명하지는 않는다. FE에서 다룬 노출/라우팅과 API 담당자의 영역을 나눠 설명한다.

## 리뷰에서 바뀐 선택

리뷰에서 context 중복 조회와 캐시 부재가 지적됐다. 이미 받은 context를 전달하는 방법과 캐싱이라는 대안을 논의했다.

우선 기존 데이터를 전달하는 좁은 변경을 선택하고 더 큰 네트워크 계층 리팩토링은 후속 기술부채로 남겼다. 공용 라우팅과 분기 우선순위를 다룬 구현 기록도 있다.

## 실험 결과로 확대하지 않는다

노출 수정과 배포를 보고한 기록이 있지만 정확한 변경·실행 매핑과 후속 결과는 별도로 확인할 대상이다. 이 사례를 실험 플랫폼 전체 설계, 통계 검정, 실험 효과의 해석으로 바꾸지 않는다.

[새 규칙과 기존 계약의 공존](/cases/budget-rule-compatibility)도 여러 경계의 영향을 좁혀 다룬 기록이다. 작은 변경을 고른 것이 큰 구조를 고려하지 않았다는 뜻은 아니다.

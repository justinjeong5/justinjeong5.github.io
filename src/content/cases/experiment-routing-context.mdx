리워드 광고에서 한 캠페인의 행동을 마친 사용자가 다음 캠페인에도 참여하도록 추천과 기간 한정 보너스를 제공했습니다. 추천 배너에서 추가 혜택을 안내했는데, 사용자가 눌러 도착한 화면에서 그 혜택이 보이지 않거나 시간이 다르게 표시되면 약속이 끊깁니다. **추천에서 시작한 참여라는 사실을 다음 화면까지 전달하는 것**이 제가 맡은 FE 작업의 중심이었습니다.

추천할 대상과 캠페인 선정, 보너스 지급은 서버가 판단했습니다. 저는 추천 API를 배너·카드에 연결하고, 선택 뒤 참여 진입과 미션·탐색 화면의 혜택 표시를 구현했습니다.

## 어느 참여에서 시작된 혜택인지 연결했다

추천 결과는 없거나 하나 또는 여러 개일 수 있었습니다. 한 개면 배너로, 여러 개면 카드를 골라 들어가게 했습니다. 하지만 추천을 누른 뒤 일반 캠페인 주소로만 이동하면 도착 화면은 사용자가 추천을 거쳤는지 알 수 없습니다.

추천 경유 진입에서는 그 문맥을 서버에 보내 새 참여 식별자를 받은 뒤 이동하도록 연결했습니다. 일반 진입은 기존 동작을 유지했습니다. 도착한 화면은 해당 참여의 응답에서 보너스와 만료 시각을 읽었습니다.

```text
추천 선택 → 추천 경유 참여 시작 → 참여 식별자 확인
                                     → 미션·탐색 화면에 같은 혜택 표시
```

FE가 지급 자격을 다시 계산하지 않았습니다. **서버가 인정한 특정 참여의 정보**를 여러 화면이 일관되게 설명하도록 한 것입니다.

## 배너를 닫는 시간과 혜택이 끝나는 시간을 분리했다

이 기능에는 두 시간이 있었습니다. 사용자가 추천을 닫은 뒤 다시 노출하지 않을 시간과, 이미 시작한 참여의 보너스가 끝나는 시간입니다. 닫힘 기록은 참여 식별자에 연결해 하루 동안 재노출을 제한했습니다. 반면 혜택의 남은 시간은 서버가 내려준 만료 시각으로 표시하고, 만료 뒤에는 참여 데이터를 다시 읽었습니다.

배너를 닫거나 다시 열었다고 보너스 지급 기간이 바뀌어서는 안 됩니다. 두 시간을 분리해야 화면의 편의 규칙이 서버의 혜택 조건을 덮지 않습니다.

추천·참여 중 목록·개별 미션에서도 기본 리워드와 보너스 적용 값을 구별해 읽도록 표시 모델을 연결했습니다. 한 화면에는 추가 혜택이 보이고 다른 화면에는 기본값만 보이면 사용자는 같은 참여를 다르게 이해합니다. 두 값이 같을 때는 불필요한 취소선도 표시하지 않았습니다.

## 확인된 결과와 제 역할

추천 경유 참여, 보너스·만료 표시, 기존 목록과 미션의 연결을 전달했습니다. 별도의 6월 실험 조건 수정에서는 게임 화면의 진입 경로를 고르는 것에 그치지 않고, 도착한 화면의 추천 조회·노출도 같은 대상 조건을 따르도록 고쳤습니다.

이후 제품팀의 실험 보고에는 설치당 광고주 과금 이벤트 평균과 구매 건수가 좋아지고, 추가 리워드 비용에도 수익률을 유지했다는 평가가 담겼습니다. 이는 추천 전략, 서버의 자격·지급 판단, 디자인과 FE가 함께 만든 **팀의 결과**입니다. 제가 직접 맡은 결과는 배너의 약속이 특정 참여의 혜택·만료 정보로 이어지고, 사용자가 보는 화면마다 같은 의미로 표현되게 한 것입니다.

리텐션 리포트에서는 같은 기준일의 사용자 묶음을 놓고 이후 날짜의 값을 비교했습니다. 운영자가 전환 수와 그 뒤의 리텐션 값을 표에서 살펴보고 CSV 파일로 내려받을 수 있도록, 저는 2021년에 화면과 내보내기를 구현했습니다.

이런 표에서는 빈칸을 어떻게 표현하는지도 비교 결과에 영향을 줍니다. 빈칸은 아직 값이 없는 것으로 읽을 수 있고, 0은 측정된 결과가 0이었다고 읽을 수 있습니다. 두 상태를 같은 값으로 바꾸면 이후 비교나 계산에서도 구분이 사라집니다.

가령 화면에서는 한 칸이 비어 있는데 파일로 내려받으면 같은 위치에 0이 있는 경우를 생각해 보겠습니다. 어느 쪽이 잘못된 자료인지 묻게 되지만, 문제는 원자료가 다르지 않아도 생깁니다. 빈 값을 채우고 화면에 표시하는 과정에서 같은 값이 서로 다르게 보일 수 있기 때문입니다.

당시에는 빠진 일자를 0으로 채우고 그래프에서 0을 빈 셀로 표시했습니다. 표와 파일로 같은 자료를 제공했지만, 지금 코드를 다시 읽어보니 변환 단계에서 '값이 없음'과 '실제 0'을 합친 부분이 남아 있었습니다. 여기서는 당시 구현한 흐름을 설명하고, 현재 돌아보며 확인한 의미의 손실도 함께 짚어보겠습니다.

## 조회 조건의 제안과 실제 화면 코드

서버 담당자에게는 FE가 광고의 시작·종료 날짜를 query로 보내는 경우와, query를 생략해 서버의 기본 기간을 사용하는 경우를 나눠 제안했습니다. 어느 쪽에서 기간을 정하느냐에 따라 화면이 설명할 조회 조건도 달라졌기 때문입니다.

실제 화면의 조회 코드는 광고 ID를 전달했고, 그 응답을 받아 표와 CSV를 만들었습니다.

## 응답을 그대로 그리지 않고 행과 열의 의미를 맞추기

리포트에서는 기준일별 코호트와 전환 수, 기준일 이후의 day-offset 값을 표의 행과 열로 바꿨습니다. 응답에 들어 있는 날짜와 배열의 순서만 따라 출력하는 것이 아니라, 각 값을 해당 날짜 열에 놓는 정규화가 필요했습니다.

빈 위치를 채우는 방식도 화면 표현과 연결됐습니다. 정규화에서는 빠진 일자의 값을 0으로 채우고, 그래프에서는 0인 위치를 빈 셀로 표시했습니다. 같은 열 구조는 만들었지만, 응답에 값이 없는 경우와 실제 값이 0인 경우가 여기서 합쳐졌습니다.

CSV도 날짜·전환 수와 일자별 값을 평평한 열로 만들었습니다. 표와 CSV가 공유한 것은 같은 응답을 날짜 열에 대응시키는 구조입니다. 그래프에서 빈 셀로 보이는 값이 CSV에서는 0으로 남을 수 있으므로, 같은 원자료를 내보낸다는 것과 같은 의미로 읽힌다는 것은 별도로 봐야 했습니다.

## 숫자 옆의 안내도 기능의 일부였다

데이터에는 표본과 실험적 성격, 완전성·갱신 시점, 작은 규모에서 제공되지 않는 값의 조건이 있었습니다. 이런 한계를 알리는 문구에도 참여했습니다. 선명한 그래프가 데이터의 조건까지 지워버리지 않도록 하는 설명이었습니다.

이 안내가 설명한 것은 표본과 집계의 조건이었습니다. 특정 빈 셀이 미관측인지 실제 0인지는 그 문구만으로 구분되지 않습니다. 데이터 전체의 사용 조건을 알리는 일과 개별 셀의 상태를 표현하는 일은 서로 다른 구현이 필요했습니다.

QA에서는 통계 서비스 상태 때문에 전체 결과를 확인하기 어려운 상황도 공유했습니다. 화면이 정상적으로 그려지는지와 실제 자료가 올바른 조건으로 조회되는지는 다른 곳에서 만나는 문제였습니다. FE와 gateway, 통계 담당자가 함께 맞춰야 하는 작업이었습니다.

## 화면과 파일에서 같은 자료를 살펴볼 수 있게

운영자는 기준일별 코호트를 같은 날짜 열에서 비교하고, 같은 자료를 CSV로 내려받아 살펴볼 수 있게 됐습니다. 데이터가 없는 화면과 표본·갱신 조건의 안내도 함께 제공했습니다. 조회한 응답을 화면과 파일에서 사용할 수 있게 만든 것이 당시의 제품 결과였습니다.

다만 빈칸과 0을 구분하는 문제까지 해결한 것은 아니었습니다. 지금 다시 평가하면 표가 나오고 파일을 내려받을 수 있는지에 더해, 두 결과가 같은 상태를 같은 의미로 전달하는지도 확인해야 한다고 생각합니다. 표시 단계에서만 수정하려 하면 변환 과정에서 이미 합쳐진 상태를 되찾을 수 없기 때문입니다.

당시에는 사용량을 무엇으로 확인할지도 질문했습니다. 지금 다시 만든다면 응답을 읽는 단계부터 값이 없는 셀과 실제 0을 나누고, 그 차이를 화면과 CSV에서 각각 어떻게 전달할지 정하겠습니다. 이는 당시 해결한 결과가 아니라, 코드를 다시 읽으며 정리한 후속 개선 방향입니다.

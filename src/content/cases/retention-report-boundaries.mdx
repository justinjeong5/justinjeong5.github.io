2021년에 코호트 리포트와 CSV를 만들었다. 운영자는 기준일별 전환 수와 이후의 리텐션 값을 화면에서 비교하고, 같은 자료를 파일로 받아 살펴볼 수 있어야 했다.

화면과 파일을 같은 자료로 만들면 같은 의미를 전달할 것이라고 생각하기 쉽다. 그런데 지금 코드를 다시 읽으면, 데이터를 행과 열로 바꾸는 단계에서 놓친 구분이 보인다. 이 글은 그 변환과 빈칸의 의미를 돌아보는 이야기다.

## 조회 조건의 제안과 실제 화면 코드

서버 담당자에게는 FE가 광고의 시작·종료 날짜를 query로 보내는 경우와, query를 생략해 서버의 기본 기간을 사용하는 경우를 나눠 제안했다. 어느 쪽에서 기간을 정하느냐에 따라 화면이 설명할 조회 조건도 달라졌기 때문이다.

실제 화면의 조회 코드는 광고 ID를 전달했다. 여기서는 그 응답을 받은 뒤 표와 CSV로 옮기는 구현을 돌아본다.

## 응답을 그대로 그리지 않고 행과 열의 의미를 맞추기

리포트에서는 기준일별 코호트와 전환 수, 기준일 이후의 day-offset 값을 표의 행과 열로 바꿨다. 응답에 들어 있는 날짜와 배열의 순서만 따라 출력하는 것이 아니라, 각 값을 해당 날짜 열에 놓는 정규화가 필요했다.

빈 위치를 채우는 방식도 화면 표현과 연결됐다. 정규화에서는 빠진 일자의 값을 0으로 채우고, 그래프에서는 0인 위치를 빈 셀로 표시했다. 같은 열 구조는 만들었지만, 응답에 값이 없는 경우와 실제 값이 0인 경우가 여기서 합쳐졌다.

CSV도 날짜·전환 수와 일자별 값을 평평한 열로 만들었다. 표와 CSV가 공유한 것은 같은 응답을 날짜 열에 대응시키는 구조다. 그래프에서 빈 셀로 보이는 값이 CSV에서는 0으로 남을 수 있으므로, 같은 원자료를 내보낸다는 것과 같은 의미로 읽힌다는 것은 별도로 봐야 했다.

## 숫자 옆의 안내도 기능의 일부였다

데이터에는 표본과 실험적 성격, 완전성·갱신 시점, 작은 규모에서 제공되지 않는 값의 조건이 있었다. 이런 한계를 알리는 문구에도 참여했다. 선명한 그래프가 데이터의 조건까지 지워버리지 않도록 하는 설명이었다.

이 안내가 설명한 것은 표본과 집계의 조건이었다. 특정 빈 셀이 미관측인지 실제 0인지는 그 문구만으로 구분되지 않는다. 데이터 전체의 사용 조건을 알리는 일과 개별 셀의 상태를 표현하는 일은 서로 다른 구현이 필요했다.

QA에서는 통계 서비스 상태 때문에 전체 결과를 확인하기 어려운 상황도 공유했다. 화면이 정상적으로 그려지는지와 실제 자료가 올바른 조건으로 조회되는지는 다른 곳에서 만나는 문제였다. FE와 gateway, 통계 담당자가 함께 맞춰야 하는 작업이었다.

## 화면과 파일에서 같은 자료를 살펴볼 수 있게

구현한 결과는 코호트 표, CSV 내보내기, 데이터 유무별 화면과 표본 조건의 안내였다. 운영자는 같은 날짜 열로 코호트를 비교하고 자료를 파일로 받을 수 있게 됐다.

지금 다시 만든다면 값이 아직 없는 셀과 실제 0인 셀을 응답을 읽는 단계부터 나누고, 화면과 CSV가 그 상태를 각각 어떻게 전달할지 함께 정하고 싶다. 표시만 바꿔서는 이미 정규화에서 잃은 구분을 되돌릴 수 없기 때문이다.

당시에는 사용량을 무엇으로 확인할지도 질문했다. 다음에는 표를 열었는지뿐 아니라, 사람들이 어떤 셀에서 비교를 멈추거나 원자료를 찾는지도 보고 싶다. 이 리포트에서 내가 계속 생각하게 되는 지점은 색을 더 잘 고르는 것보다, 사용자가 읽는 빈칸에 어떤 상태를 남길 것인가다.

## 확인 근거와 공개 범위

API 제안·문구와 데이터 제약 협의, 화면·CSV 구현과 리뷰를 대조했습니다. 통계의 정확성이나 실제 이용률을 입증하는 자료는 아닙니다.

이 글은 원문을 대조한 공개용 재구성입니다. 내부 코드·협의 원문·고객 정보는 공개하지 않으므로 방문자가 원문을 직접 검증할 수 있는 자료는 아닙니다.

## 그래프 이전에 맞춰야 할 의미

광고 운영자가 코호트 리포트와 CSV를 사용할 수 있게 하는 작업에서 조회 날짜의 의미를 서버와 맞췄다. 날짜를 보내는 경우와 생략한 경우의 기본값 계약을 제안했다.

데이터의 샘플링·실험적 성격을 알리는 문구에도 참여했다. 그래프가 만들어졌다는 사실이 데이터가 모든 상황을 정확하게 설명한다는 뜻은 아니었다.

## 구현과 확인 조건

FE/gateway 리뷰와 리포트·CSV 구현 기록이 있다. QA가 통계 서비스의 상태에 의존한다는 제약을 공유하고, 사용량을 무엇으로 확인할지도 질문했다.

사용 추적을 질문한 기록이 실제 계측 운영이나 그 결과를 이용한 제품 판단을 입증하지는 않는다. 통계 방법과 데이터 품질 책임도 화면 개발의 책임과 구분한다.

## 지표와 제품 성과를 구분한다

여기서 남기는 것은 조회 계약·리포트 구현·한계 표시다. 리텐션을 보여주는 리포트를 만들었다고 사용자 리텐션이 증가했다는 성과가 생기지 않는다. 다른 리포트의 준비·공개 기록도 한 프로젝트의 끝으로 합치지 않는다.

[부분 결과를 드러내는 운영 화면](/cases/bulk-partial-results)과 함께 보면, 데이터나 저장 상태를 사용자가 어떻게 읽을지 협의한 과정이 보인다.

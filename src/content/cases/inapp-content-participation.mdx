기존 콘텐츠는 앱 밖의 웹페이지를 열어 참여했습니다. 같은 콘텐츠를 앱 안에서도 끝낼 수 있도록 새 진입 경로를 만들 때, 화면을 여는 방법만 바꾸면 충분하지 않았습니다. 앱 안에서 시작했다고 표시한 뒤 실제로는 외부 웹으로 열리면, 이어지는 참여 요청이 잘못된 실행 환경을 읽을 수 있었습니다.

저는 인앱 참여의 진입·복귀·완료 화면을 맡고, 서버·디자인·매체 앱 담당자와 기존 외부 경로를 함께 확인했습니다. 광고 공급사를 연결하는 계층은 동료가 맡았습니다. 먼저 핵심 참여를 출시하고 교차 추천은 별도 작업으로 남겼습니다.

## 추적 링크와 사용자가 도착할 URL은 같지 않았다

상단 카드와 오퍼월 등 진입점마다 추적 링크를 만드는 방식이 달랐습니다. 사용자가 실제로 도착할 콘텐츠 주소와, 그 주소를 감싼 추적 링크를 같은 값으로 다루면 인앱 참여 여부가 목적지에 전달되지 않을 수 있었습니다.

서버가 최종 콘텐츠 주소에 인앱 참여 정보를 넣고, 그 뒤 추적 링크로 감싸서 내려주는 계약에 맞췄습니다. 화면에서는 이미 만들어진 추적 링크를 임의로 고치지 않았습니다.

```text
실제 콘텐츠 URL에 인앱 참여 여부 연결
  → 추적 URL로 감싸기
  → 사용자 진입
  → 콘텐츠가 인앱 참여 여부를 읽고 참여
```

클라이언트는 표식을 읽어 실행 방법을 정했습니다. 표식이 있다는 것만으로 실제 앱 실행이나 시청을 인증하지는 않았습니다.

## 폴백에서는 실패한 실행의 문맥도 바꿨다

앱 인터페이스 호출에 실패해 외부 브라우저를 열면 내부 콘텐츠의 인앱 표식을 제거했습니다. 실제 실행은 외부인데 URL은 인앱이라고 말하면 다음 요청도 잘못된 조건을 읽을 수 있었습니다.

같은 이름의 query라고 아무 목적지에서 지우지는 않았습니다. 내부 콘텐츠의 표식만 다루고 광고주의 동명 파라미터는 보존했습니다. 열기 방식의 폴백이 광고주 URL의 의미까지 바꾸면 안 됐습니다.

화면 복귀를 놓치지 않도록 열기 전에 감시를 시작하고, 열기에 실패하면 감시도 끝냈습니다.

## 먼저 출시한 뒤 완료 표시의 범위를 좁혔다

8월 19일 공동 상용 출시 뒤 동료들의 실제 정상 참여 확인을 받았습니다. 이후에는 완료 UI를 맞추기 위한 로컬 신호를 추가하고 적용 조건을 보완했습니다.

출시 뒤에는 이전 참여의 완료 기록이 새 카드에 적용되지 않도록 보완했습니다. 같은 콘텐츠여도 광고 할당·참여 회차가 다르거나 지금 클릭하기 전의 기록이면 이번 완료로 표시하지 않았습니다. 이 조건은 8월 하순 후속 변경과 회귀 테스트에 반영했습니다.

로컬 기록은 완료 화면을 맞추는 데만 사용했습니다. 외부 경로의 전환 확인과 승인·지급은 서버 판정을 따르므로, 빠른 화면 표시를 실제 지급의 근거로 확대하지 않았습니다.

## 새로운 실행 경로를 넣으면서 기존 참여를 지키기

8월 19일 공동 출시로 기존 콘텐츠를 앱 안에서도 참여할 수 있게 됐고, 앱 실행이 실패하면 외부로 이어지는 경로도 유지했습니다. 출시 뒤 완료 표시의 범위를 좁힌 보완은 그다음 단계였습니다.

제가 확인한 핵심은 새 경로의 정상 동작뿐 아니라, 실패해 기존 경로로 돌아간 뒤에도 **다음 요청이 실제로 열린 환경을 읽는가**였습니다.

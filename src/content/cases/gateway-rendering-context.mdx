참여 링크를 열면 중간 단계에서 앱 안의 화면과 외부 웹 화면 중 목적지를 골랐습니다. publisher 초기화를 기다리고 capability, 즉 해당 환경이 제공하는 기능을 읽어 어느 화면을 실행할지 결정하는 흐름이었습니다.

중간 단계에서 soft navigation을 하면 라우터를 전환하고 목적지를 마운트하는 과정이 추가됩니다. 특정 Android WebView에서 빈 화면을 재현한 동료와 조건을 살펴본 뒤, 저는 같은 경로에서 목적지 컴포넌트를 렌더하는 PoC와 후속 구현을 진행했습니다. 이동을 생략하려면 **페이지를 이동하지 않는 대신 무엇을 더 동기화해야 하는가**도 확인해야 했습니다.

## 목적지보다 먼저 준비될 입력을 구별했다

publisher가 아직 준비되지 않았는데 capability를 읽거나, target이 URL에 반영되기 전에 외부 웹 모드를 렌더하면 다른 실행 환경으로 시작할 수 있었습니다. 기다릴 조건을 나누고 준비된 결과로 목적지를 선택했습니다.

capability 조회가 실패한 경우는 외부 웹으로 연결하는 fallback을 사용했습니다. 성공·실패의 경로가 모두 같은 화면 진입을 설명해야 했습니다.

## query는 바꾸되 pathname은 유지했다

soft navigation hop 대신 같은 route에서 컴포넌트를 합성했습니다. target을 바꿀 때는 search만 `history.replaceState`로 반영해 pathname과 basePath를 유지했고, 반영된 target을 읽은 뒤 올바른 모드를 렌더했습니다.

target을 URL에 반영하기 전에 모드를 결정하면 이전 입력으로 다른 화면이 시작될 수 있었습니다. 그래서 URL을 바꾸고 반영된 target을 읽은 뒤에 목적지를 렌더하도록 순서를 연결했습니다.

target을 주입한 변화 때문에 capability effect가 다시 실행되지 않도록, 그 입력에서는 target을 제외했습니다. 실행 환경을 알아내기 위한 입력과 알아낸 환경을 URL에 남기는 출력을 구별한 것입니다.

## 목적지만 렌더하면 원래 layout의 책임이 빠진다

페이지 이동을 생략하면 원래 목적지 layout을 통과하지 않습니다. 목적지 컴포넌트만 넣는 것으로는 theme과 외부 웹의 광고 설정이 따라오지 않았습니다.

공유 shell을 재사용해 직접 렌더에서도 기존 구성을 유지했습니다. 목적지 페이지로 이동할 때와 같은 설정으로 실행하려면, 컴포넌트 내용뿐 아니라 원래 layout이 적용하던 theme과 광고 설정도 함께 적용해야 했습니다.

## 기다림과 늦은 결과를 다른 입력으로 검증했다

publisher 대기, capability 실패의 fallback, target 반영 전의 대기와 언마운트 조건을 구분했습니다. 타이머가 늦어지는 조건과 중복 BI 발행도 테스트 사례에 남겼습니다.

| 조건 | 지켜야 할 결과 |
| --- | --- |
| publisher가 준비되지 않음 | 목적지 판단을 앞당기지 않음 |
| capability 조회 실패 | 외부 웹 fallback |
| URL target이 아직 반영되지 않음 | 잘못된 모드로 먼저 시작하지 않음 |
| 컴포넌트 종료 | 이후 결과가 종료한 흐름을 이어가지 않음 |
| 같은 진입을 다시 읽음 | 계측을 중복 발행하지 않음 |

이 구현은 6월에 main으로 통합됐습니다. 당시 기기의 모든 흰 화면이 없어졌거나 브라우저 엔진의 원인을 확정했다는 결과와는 구별합니다. 제가 바꾼 것은 중간 이동과 목적지 실행을 연결하는 FE 구조였습니다.

## 이동을 줄이려면 없어지는 책임도 찾아야 했다

같은 경로에서 목적지를 렌더하면서 중간 이동의 hop은 없어졌습니다. 그 대신 URL이 반영될 때까지 기다리고, 원래 목적지 layout이 준비하던 theme과 광고 설정을 직접 렌더에도 연결해야 했습니다. 기다림과 준비를 어디에서 처리할지가 바뀐 구현이었습니다.

이 작업을 돌아보면, 목적지 컴포넌트를 넣는 것만으로는 이동을 생략할 수 없었다고 생각합니다. 다음에 진입 흐름을 줄일 때도 생략할 화면이 준비하던 상태와 설정을 먼저 확인하고, 늦은 결과가 종료한 흐름을 다시 이어가지 않는 조건까지 살펴보려고 합니다.

채팅 화면은 메시지 목록처럼 보이지만, 메시지를 받는 경로와 받은 값을 반영하는 상태에 따라 동작이 달라집니다. 개인 채팅 앱의 공개 PR을 다시 읽으면서, 이 글에서는 실제로 바꾼 메시지 전달과 상태 갱신을 설명하려고 합니다.

## 메시지를 받는 경로와 상태를 갱신하는 방법

[메시지·연결 변경 PR](https://github.com/justinjeong5/j-chat/pull/23)에서는 WebSocket transport와 메시지 전달, 화면 상태 갱신을 변경했습니다. REST로 전송한 뒤 응답 상태를 바꾸는 경로 대신 메시지 이벤트를 전달하고, 받은 메시지는 functional update로 반영하는 작업이었습니다.

## 방을 떠나도 연결의 일은 남는다

[방 입퇴장 PR](https://github.com/justinjeong5/j-chat/pull/24)에는 방 입장·퇴장 UI와 이벤트가 있습니다. membership API와 UI 이동에 이벤트 통지, 연결 등록과 화면 정리를 연결했습니다. 방을 떠나며 화면을 옮겨도 연결을 정리하는 작업은 따로 다뤄야 했습니다.

개인 프로젝트를 소개할 때도 큰 이름보다 실제로 바꾼 동작을 남기려고 합니다. 이 두 PR에서는 메시지를 어떻게 반영하는지와 방을 떠난 뒤 연결을 어떻게 정리하는지를 함께 다뤘습니다. 업무의 [최신 요청의 결과와 정리](/cases/latest-request-boundaries)는 별개의 흐름이지만, 상태를 갱신한 뒤에도 남는 작업을 확인한다는 질문은 이어집니다.
